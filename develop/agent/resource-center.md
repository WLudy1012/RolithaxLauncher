# 资源中心

## 产品目标

资源中心把模组、插件、整合包和数据包组织成接近购物清单的流程：先选择目标实例，再浏览资源、选择版本、统一检查依赖和冲突，最后一次性安装。服务端专用资源要按目标核心过滤，客户端与服务端都需要的模组要能生成可复制清单。

## 数据来源

- 首期 Provider：Modrinth API v3。
- 服务端核心：MSLAPI 服务端核心接口。
- Provider 接口为后续 Hangar、SpigotMC、GitHub Release 和公开 CurseForge 镜像预留扩展点。
- Modrinth 搜索只识别 `facets`（`project_types`、`game_versions`、`categories` 作加载器）；`project_type`、`game_version`、`loader` 查询参数会被忽略并返回全站结果，不能用来筛选。很多项目同时属于 `mod` 与 `plugin`，解析类型时优先采用当前请求的分类。
- 云端安装由 `mslx-plugin-rolithax` 在 Daemon 所在主机完成，避免客户端下载后再上传造成重复流量。

## 缓存与刷新

Room 保存项目、版本、同步游标、ETag 和购物清单；Paging 负责列表展示，Flow 负责状态更新。首次加载允许在兼容性过滤后继续扫描远端页面；之后按更新时间或 ETag 增量刷新，并在网络失败时保留离线缓存。

UI 必须区分以下状态：

- 首次加载中。
- 远端刷新失败但缓存可用：继续显示缓存，同时提供错误说明和重试。
- 远端还有内容但首批过滤后为空：显示继续扫描，而不是误报没有资源。
- 已确认到达末尾且为空：才显示没有匹配资源。
- 版本接口失败：显示失败和重试，不把失败伪装成没有可安装版本。

快速切换项目、目标实例或 Provider 时，旧请求不能覆盖当前项目的版本列表和加载状态。可以取消前一请求，也可以用请求代际和当前项目 ID 校验响应。

## 安装与校验

- 本地实例：在目标实例目录流式下载、校验并安装，不一次性读入大文件。
- 云端实例：向插件提交安装任务，由 Daemon 所在机器下载和安装，客户端轮询任务状态。
- Modpack override：限制单文件大小、总解压大小和条目数量，限制目标路径并拒绝路径穿越。
- 版本选择同时考虑游戏版本、加载器、服务端兼容性和兼容元数据是否完整。元数据缺失时应显示“兼容性未知”，不要与明确不匹配混为一谈。
- 统一检查必需依赖、冲突、服务端/客户端安装范围，并把自动加入的依赖和阻断原因展示给用户。

## 内存与界面

Room 分页、详情按需加载、图片使用磁盘缓存，安装包和下载响应采用流式处理。列表图标要限制响应体、预读图片尺寸并按显示尺寸解码。Snackbar、错误条、空态和重试入口都应由稳定的 Compose 状态持有，避免重组时丢失队列或把缓存状态覆盖掉。
