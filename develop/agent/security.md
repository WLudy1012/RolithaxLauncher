# 安全、隐私与日志

## 凭据与设置

Daemon 连接凭据使用 Android Keystore 支持的 AES-GCM 加密后写入 DataStore。备份规则排除依赖 Keystore 才能解密的设置；导出/导入使用独立的认证加密归档，不导出 Keystore 密钥本身。加密、解密、解析或迁移失败时清理或拒绝写入，不能把原文作为回退副本落盘。

用户中心默认遮蔽敏感凭据，只在明确操作后临时显示或复制。任何日志、崩溃报告、截图说明、Issue 自动评审输入和文档都不能包含凭据值。

## 网络安全

- Daemon 地址默认使用 HTTPS；明文 HTTP 只有在用户明确确认并且属于可信内网时才可用。
- Daemon 自签证书信任只作用于用户配置的 Daemon，不扩展到 MSLAPI、GitHub 或其他公共 API。
- HTTP 日志只记录方法、协议、主机、端口、状态码和耗时，不记录查询参数、完整请求头或响应正文。
- API 错误需要脱敏后再展示和记录；地址、路径、Token、Bearer、Cookie、授权头和 API Key 统一脱敏。

## 文件和归档

- 大文件上传、下载、图标和安装包必须流式处理，禁止无界 `readBytes()`。
- 所有临时文件写入缓存目录，校验成功后原子替换目标；异常退出清理临时文件。
- ZIP/TAR/整合包解压要同时限制路径、单文件大小、总大小和条目数量，并用 canonical path 校验目标仍位于实例目录内。
- 备份恢复使用版本清单、认证加密、路径过滤和大小/条目上限；恢复到临时目录完成校验后再落地。
- 运行实例不允许删除、迁移或恢复覆盖；删除必须有确认步骤，不能让运行中的服务端目录被直接递归删除。

## 本机运行安全

本机开服涉及进程内 JVM、公共存储、前台服务、唤醒锁和可选 Shizuku 权限。每项能力都要在 UI 中显示真实权限状态；没有授权时只能提示操作方法，不执行未授权的系统写操作。标准输入输出重定向、Native fd、JVM 和日志线程必须在成功与失败路径分别清理。

## 更新和资产

应用更新、JRE、服务端核心和资源文件需要检查最终下载域名、协议、文件类型和 SHA-256。缺少可信摘要、响应被截断或摘要不匹配时必须失败关闭；不能因为镜像不可用而降级到无校验下载。更新安装前检查 APK 文件类型，避免把错误页面交给系统安装器。

## 运行日志

`AppLogger` 提供可查看、复制、导出和清理的日志，按大小轮转并清理过期文件。Release 默认关闭 verbose/debug，只保留必要的信息、警告和错误。异常记录应包含异常类型、脱敏后的消息、阶段和关联信息，不能为了脱敏而丢掉定位问题所需的结构。

## Issue 与自动评审

崩溃报告模板只要求崩溃报告；普通 Bug 模板需要版本、日志、描述、复现步骤和页面截图；新功能建议需要版本和功能描述。自动评审只读取仓库代码和只读历史，输出结论、置信度、代码定位和原因假设；评审失败不能阻断 Issue 提交，也不能把受保护凭据传给模型。
