# 本机开服与运行时

## 存储布局

本机数据以 `filesDir/mslx/` 为私有根目录，公共实例可放在设备的 `MSLX/servers/` 目录。实例目录名在两个存储根之间保持全局唯一，路由和通知只传递安全的目录名，不用显示名称反推路径。

```text
filesDir/mslx/
├── runtime/<运行时 ID>/     Java 运行时
├── servers/<实例目录>/      server.jar、配置、元数据、世界与日志
└── cache/                   下载和暂存文件

公共存储/MSLX/servers/<实例目录>/
```

私有目录不需要额外授权，公共目录需要 Android 11 及以上的“所有文件访问”授权。没有权限时创建流程应回退或明确提示，不能假装公共目录写入成功。旧布局迁移必须保留用户数据，失败只影响迁移项，不阻断应用启动。

## 实例文件

`ServerFiles.complete` 负责幂等补全实例文件，并且绝不覆盖用户已经修改的内容：

- `server.jar`：核心下载后的固定文件名。
- `eula.txt`：与 Daemon 约定一致的同意文件。
- `server.properties`：服务端常见配置的默认值。
- `instance.json`：名称、目录、核心、版本、运行时、内存、JVM 参数、保活和创建/更新时间等元数据。
- `ops.json`、白名单、封禁名单等空数据文件。
- `logs/`、`plugins/`、`mods/`、世界目录等运行期目录，按核心类型预建。

实例目录名必须经过消毒、长度限制和路径边界校验。删除、导入、恢复和重命名都不能越过允许的实例根目录；运行中的实例禁止删除或迁移。

## 引擎选择

本机开服通过 `LocalServerManager` 收敛实例解析、文件补全、运行时校验和引擎选择：

1. 加载实例元数据并解析存储位置。
2. 检查核心文件、运行时和游戏版本匹配关系。
3. 读取全局本机开服设置，合并实例级覆盖配置。
4. 若启用增强模式且 Shizuku 已授权，使用 `ShizukuShellEngine` 启动真实 Java 子进程。
5. 否则使用 `InProcessJvmEngine`，通过 Native 桥接在应用进程内创建 JVM。

### 进程内 JVM

Native 层使用 `dlopen` 加载 `libjvm.so`，查找 `JNI_CreateJavaVM`，再由 Kotlin 调用服务端主类。标准输入、输出和错误输出通过受控管道连接控制台。JVM 创建失败时必须关闭管道、停止日志泵并恢复或避免修改进程级 fd；首次调用前必须完成所有可失败的路径和核心校验。

进程内模式在同一个 Android 进程中只能创建一个 JVM。停止后不能保证原地重启，界面需要提示用户完全退出 App 后再启动，或改用 Shizuku 增强模式。

### Shizuku 增强模式

增强模式用于真实 Java 子进程、多实例并发、原地重启和跨 Java 版本。没有 Shizuku 或权限不足时只给出授权指引，并自动回退到基线引擎；不能偷偷执行未授权的系统写操作。

## Java 运行时

运行时由 `LocalJreManager` 注册表管理。运行时选择应根据核心版本给出建议并在启动前做硬性兼容检查：运行时过旧直接阻止启动并给出可操作的替换建议，运行时更新但核心较旧只提示风险。运行时归档来源可以有镜像和上游回退，但每个可安装资产都必须有可信摘要和结构校验。

运行时资源可以内嵌在完整版 APK，也可以由精简版在设备上按需下载。缺少可信资产时保持失败关闭，不允许为了“能安装”而取消校验。

## 保活和网络

本机服务端使用前台服务和常驻通知保活，通知提供停止入口。可选的屏幕常亮、唤醒锁、局域网/热点和防火墙诊断只负责提示或经过明确授权的操作；没有 root、Shizuku 或系统权限时不得宣称已经修改系统防火墙。

本机控制台和远程控制台通过同一 `ConsoleController` 契约提供状态、日志、命令、启动、停止、重启和 EULA 事件，界面不应根据引擎类型复制一套交互。
