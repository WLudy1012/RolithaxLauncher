# Rolithax Schema 2

Native library: `rolithax_schema`; CLI: `rolithax-schema`. CLI reads one JSON request per stdin line and writes one JSON response per stdout line, retaining one session until EOF. No diagnostic output is written to stdout.

C ABI: `uint64_t rolithax_schema_create()`, `void rolithax_schema_destroy(uint64_t)`, `char* rolithax_schema_request(uint64_t, const char*)`, `void rolithax_schema_free(char*)`. Returned strings are UTF-8. Responses are `{ "ok": true, "data": ... }` or `{ "ok": false, "error": { "file": "...", "line": 1, "message": "..." } }`.

Requests use root fields: `op`, `source`, `allowedCommands`, `text`, `actionId`, `arguments`, `expectedRevision`. Operations: `inspect` (source → metadata), `reload` (source + allowedCommands → snapshot), `log` (text → changed boolean), `snapshot`, `command` (actionId + arguments + expectedRevision → string/null), `reset`, `gap`, `restore`. `inspect` returns `id`, `version`, `server`, `title`, `nodes`, `initial`, `commands` (action ID → command template), `engine`, `sdkVersion`.

Source is `{manifest: "JSON text", ui: "XML text", rules: "YAML text", lua: "Lua source text"}`. Missing rules/lua default empty. Schema 1 manifests and their rules remain supported. Schema 2 manifest requires `id`, `version`, `sdkVersion: 2`, `server`, `engine: "yaml" | "lua"`; optional `name`, `description`, `compatibility` object. IDs, semantic versions and server symbols retain v1 constraints. Manifest <= 16 KiB; XML/YAML <= 64 KiB each; Lua <= 128 KiB.

UI retains `panel`, `section`, `text`, `status`, `list`, `field`, `button`, and adds `row` (container), `metric`, `progress`, `badge` (require field), `divider` (no field). All controls have id/label. Optional Schema 2 attributes: `description`, `tone`, `unit`, `placeholder`. No HTML, external entities, scripts or arbitrary attributes. Maximum 128 nodes and depth 8. `progress` values are decimal percentages 0–100; renderer clamps untrusted display values. Snapshot node extensions are nullable strings; existing children/field/action stay unchanged.

YAML remains a bounded two-space mapping subset with double-quoted scalar values. Sections: `initial`, `rules`, `commands`. Rules retain prefix/suffix/contains, field, operation set/append, and value/capture. Schema 2 additionally supports captures `number` (first signed decimal from matched middle) and `percent` (first decimal followed by `%`). Numeric captures scan linearly and reject values longer than 32 bytes. No arbitrary regular expressions.

Schema 2 command text may contain multiple fixed words and `{input}` placeholders, <= 256 bytes. Declare placeholders with `inputs: "target:player,group:token,radius:integer"`; supported validators: player (Java username), token (1–128 ASCII alphanumeric or `_ . : / + -`), integer (optional minus and <= 10 digits), number (optional minus, decimal, <= 32 bytes). Every declared input needs an XML field. Inputs cannot contain whitespace, quotes, CR/LF or shell separators. All arguments must match exactly; commands are returned only after explicit action grant and matching package revision. Schema 1 retains its original command-name/optional-player constraints.

Lua returns a table: `{ initial = { field = "value" }, commands = { action = { text = "lp info" } }, on_log = function(line, state) return { field = "new value" } end }`. Commands use the same `text` and optional `inputs` strings as YAML. `state` is a copy; only the returned update table changes state. Update keys must exist in initial; values must be UTF-8 strings <= 512 bytes, except newline-separated lists <= 8192 bytes. Lua never dispatches commands. Standard math/table/string/utf8 libraries are restricted; no os/io/package/debug, load/loadfile/dofile/require, coroutine or bytecode. Each call is instruction and memory limited; errors preserve the last snapshot and revoke no existing package during failed reload. Plugins are source `.lua` inside prebuilt ZIPs, not executable DLLs or Lua bytecode.

All engines strip common Minecraft log envelopes and SGR colors before matching, reject control characters, and keep bounded evidence/history. Data cannot authorize actions. A gap marks the snapshot stale. Reload validates and replays before swapping, and increments packageRevision to invalidate stale confirmations.

Lua 5.5.1 sandbox limits are 4 MiB allocated script memory, 100,000 work units and a 25 ms deadline per load/callback. VM instructions and estimated C library work consume the same budget; the VM hook checks every 100 instructions and allocations also check the deadline. `pcall`, `xpcall`, `collectgarbage`, `print`, `warn`, metatable access and `string.dump/pack/packsize/unpack` are unavailable. Pattern functions permit at most 8 KiB input, a 256-byte pattern and one quantifier; quantified patterns must begin with `^`. `gmatch` permits no quantifiers because Lua does not treat its `^` as an anchor. Balanced/frontier/backreference patterns are rejected. `string.find(..., true)` performs plain matching. Table operations are limited to 8192 elements, including explicit move/unpack ranges. These bounds also cover C library work that instruction hooks cannot interrupt. Use string slicing or small simple matches for log parsing. Host allocation of a bounded state copy has a 256 KiB reserve outside the script budget. Lua diagnostic filenames are `business.lua`.
